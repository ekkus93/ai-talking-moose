# AI Talking Moose — KittenTTS Local Speech Synthesis Specification

**Document:** `SPEC(20260909-120003).md`  
**Repository:** `ekkus93/ai-talking-moose`  
**Baseline:** `80027a70815bfa8db6c9faa03b3a8e7501f2fe4d` (`master`, 2026-09-09)  
**Companion tracker:** `docs/TODO(20260909-120003).md`  
**Status:** Proposed implementation specification  
**Scope:** Add a CPU-first, offline-capable KittenTTS standalone speech-synthesis provider while preserving the existing Gemini TTS and Gemini Live paths.

---

## 1. Purpose

Talking Moose currently has a provider-neutral `SpeechSynthesizer` trait, but production standalone TTS is always constructed as `GoogleSpeechSynthesizer`. Typed replies, ambient remarks, canned reactions, and voice auditions converge on the authoritative standalone speech path, which then feeds the shared Rust/CPAL playback system.

This project adds **KittenTTS as a local standalone TTS provider** without replacing Gemini TTS and without changing Gemini Live voice conversations.

The desired product behavior is:

```text
Standalone speech provider

  Google Gemini TTS
      OR
  Local KittenTTS

                 ↓
        AudioStreamData / PCM
                 ↓
     existing AudioPlayback / CPAL
                 ↓
     speakers + RMS mouth animation
```

The feature must be small enough for ordinary desktop use, require no GPU, work on Linux and macOS, preserve the current cancellation/playback semantics, and make privacy/fallback behavior explicit.

## 2. Current Production Baseline

At baseline `80027a70815bfa8db6c9faa03b3a8e7501f2fe4d`:

1. `SpeechSynthesizer` is provider-neutral.
2. `AppState::get_speech_synthesizer()` always constructs `GoogleSpeechSynthesizer`.
3. standalone speech paths converge on `commands::speech::invoke_standalone_speech()`.
4. standalone synthesis returns PCM through `AudioStreamData` and reuses `AudioPlayback`.
5. `AudioPlayback` owns device selection, resampling, gain, bounded queueing, output-level diagnostics, and mouth-shape generation.
6. `StandaloneSpeechController` owns preemption/cancellation and flushes stale queued speech.
7. the current TTS model is `gemini-2.5-flash-preview-tts`.
8. the current default Gemini voice is `Fenrir`.
9. `AppSettings.settings_version == 3`.
10. `tts_voice` is currently shared between standalone TTS and Gemini Live session configuration.
11. `tts_model` currently means Google standalone TTS model.
12. the repository itself is Apache-2.0 licensed.

The implementation MUST preserve the successful standalone speech architecture rather than adding a second playback stack.

## 3. Selected Local TTS Family

### 3.1 Model family

The selected local speech family is **KittenTTS v0.8**.

The initial quality-first model target is:

```text
KittenML/kitten-tts-mini-0.8
```

Current upstream properties reviewed for planning:

- 80 million parameters;
- approximately 79–80 MB model footprint;
- ONNX inference;
- 24 kHz output;
- CPU operation with no GPU requirement;
- eight voices: Bella, Jasper, Luna, Bruno, Rosie, Hugo, Kiki, Leo;
- model metadata declares Apache-2.0.

The exact production artifact identity is **not frozen by this planning document**. Implementation must pin an immutable source revision plus exact file sizes and SHA-256 digests before any installer is accepted.

### 3.2 Optional later variants

Kitten Micro, Nano, and Nano INT8 are not required by this project. The catalog/runtime should not be needlessly hard-coded so that a later task can add them, but this implementation has one required local model: Kitten Mini 0.8.

The project MUST NOT silently substitute Nano or another Kitten model if Mini is unavailable.

## 4. Licensing Is a Hard Gate

The user explicitly rejected Piper as an attractive default partly because of its current GPL licensing situation. The KittenTTS integration must not recreate that problem accidentally through a phonemizer or inference wrapper.

### 4.1 Known upstream facts

As of this specification:

- KittenTTS source is advertised as Apache-2.0.
- `KittenML/kitten-tts-mini-0.8` declares Apache-2.0.
- sherpa-onnx is generally Apache-2.0 and supports KittenTTS v0.8 through Rust/C/C++ APIs.
- common KittenTTS text front ends use eSpeak NG or eSpeak-derived data for grapheme-to-phoneme conversion.
- eSpeak NG itself is GPL-3.0-or-later.
- sherpa-onnx Kitten model packages conventionally contain `espeak-ng-data`.
- the official KittenTTS Python package depends on `espeakng_loader` and `phonemizer`.

Therefore **“KittenTTS is Apache-2.0” is not sufficient evidence that an arbitrary complete KittenTTS runtime payload is compatible with Talking Moose's Apache-2.0 distribution policy.**

### 4.2 Required licensing policy

Before production integration is chosen, record the complete shipped/runtime dependency inventory for:

- Kitten model files;
- voice embeddings;
- tokenizer/token files;
- text-normalization code/data;
- phonemizer code/data;
- ONNX Runtime;
- any wrapper/runtime library;
- notices and attribution files.

No GPL/copyleft code or data may be bundled, statically linked, dynamically linked, copied into application resources, or downloaded as an application-managed runtime dependency **unless the owner explicitly approves that licensing consequence after the audit**.

The default implementation objective is to preserve the repository's permissive distribution posture.

### 4.3 Runtime candidates

The model choice is fixed; the runtime carrier is deliberately not frozen until the license spike is complete.

Candidates include:

1. a direct Rust/ONNX implementation using permissively licensed components;
2. an audited Rust KittenTTS wrapper with GPL phonemization features disabled plus a permissive English G2P implementation;
3. sherpa-onnx only if the exact production build and data payload pass the licensing gate.

A promising feasibility candidate for English G2P is an eSpeak-free MIT-licensed IPA phonemizer such as `piper-plus-g2p`, but compatibility with KittenTTS's expected IPA/token stream MUST be tested against reference outputs before selection.

No implementation may use “it sounds approximately correct” as a substitute for a dependency/license inventory.

## 5. Product Goals

### 5.1 Primary goals

1. Add a user-selectable **Local KittenTTS** provider for standalone speech.
2. Keep existing **Google Gemini TTS** available.
3. Keep **Gemini Live native-audio conversations** unchanged.
4. Run Kitten inference on CPU with no GPU requirement.
5. Support Linux x86_64 and macOS arm64/x86_64 build/package targets used by the project.
6. Keep user text on-device whenever Local KittenTTS is selected.
7. Reuse the existing `SpeechSynthesizer` → `AudioPlayback` → CPAL path.
8. Preserve bounded playback, barge-in, cancellation, speech bubbles, and mouth animation.
9. Make local model installation explicit, integrity-checked, cancellable, and recoverable.
10. Avoid silent Google↔Local fallback in either direction.
11. Keep ordinary CI model-weight-free.
12. Add focused real-model acceptance with measured CPU performance.
13. Preserve permissive licensing unless the owner explicitly approves otherwise.

### 5.2 Secondary goals

1. Keep the local runtime warm between utterances so every sentence does not reload the model.
2. Keep the model-install/UI experience parallel to existing Local LLM/Moonshine lifecycle patterns where that reuse is sound.
3. Expose useful local TTS diagnostics without exposing spoken text.
4. Keep provider-specific controls truthful: do not pretend Kitten supports pitch if the chosen runtime only exposes speed.
5. Leave architecture open to additional permissively licensed local TTS models later.

---

## 6. Explicit Non-Goals

This project does **not** require:

1. replacing Gemini TTS;
2. replacing Gemini Live;
3. making live microphone conversations fully local;
4. local ASR changes;
5. Local LLM changes;
6. GPU/CUDA/CoreML acceleration;
7. voice cloning;
8. user-supplied arbitrary TTS models;
9. training or fine-tuning KittenTTS;
10. multilingual local TTS in V1;
11. streaming synthesized audio before the first complete local inference chunk unless the selected runtime naturally provides a safe implementation;
12. DSP pitch shifting;
13. changing the shared CPAL playback architecture;
14. bundling the ~80 MB model into ordinary source control or ordinary CI artifacts.

## 7. Provider and Settings Model

### 7.1 Independent standalone TTS provider

Add a typed provider enum, conceptually:

```rust
#[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "snake_case")]
pub enum TtsProvider {
    Google,
    Local,
}
```

`TtsProvider` is independent of:

- `TextProvider`;
- `AsrMode`;
- Gemini Live provider selection.

A user may therefore choose combinations such as:

```text
Local LLM + Local KittenTTS
Google text + Local KittenTTS
Local LLM + Google TTS
Gemini Live voice conversation (always Live native audio)
```

### 7.2 Split the overloaded current voice setting

The current `tts_voice` is used by both standalone TTS and Gemini Live. Local Kitten voice IDs cannot safely occupy that same field.

The settings schema MUST separate at least:

```text
tts_provider
google_tts_model
google_tts_voice
local_tts_model
local_tts_voice
live_voice
speaking_rate
pitch
```

`live_voice` remains a Gemini Live voice.

`google_tts_voice` remains a Gemini standalone TTS voice.

`local_tts_voice` is one of the Kitten voice catalog entries.

### 7.3 Versioned migration

Increment `CURRENT_SETTINGS_VERSION`.

For an existing v3 profile:

- migrate legacy `tts_model` → `google_tts_model`;
- migrate legacy `tts_voice` → both `google_tts_voice` and `live_voice`;
- set `tts_provider = Google` to preserve existing behavior;
- initialize `local_tts_model` to the frozen Kitten Mini catalog default;
- initialize `local_tts_voice` to the voice selected by the P0 audition/quality decision.

Legacy fields MUST NOT survive in the normalized persisted v4 representation.

Future-version fail-closed behavior from the Local LLM remediation must remain intact.

### 7.4 New-profile default

This project **does not automatically change the product default to Local TTS** merely because the feature exists.

The initial implementation should preserve Google TTS as the new-profile default unless the owner explicitly changes that policy after local real-model/voice acceptance.

## 8. Provider Capabilities and Voice Catalogs

Provider-specific controls must be explicit.

The backend should expose typed TTS provider/model/voice metadata sufficient for the frontend to render only supported controls.

At minimum:

```text
provider ID
display name
local/cloud classification
model ID/display name
voice ID/display name
sample rate
supports speaking-rate/speed
supports pitch
requires model installation
license summary
```

For KittenTTS V1:

- language: English;
- sample rate: 24,000 Hz;
- voice count: 8;
- speed/rate: supported;
- pitch: not supported unless the selected audited runtime exposes a real model-level control.

The frontend MUST disable or hide pitch while Local KittenTTS is selected rather than silently implying it changes local synthesis.

The stored Google pitch value may be preserved for later switching back to Google.

## 10. Installation and Integrity

### 10.1 Storage

Use an application-managed local TTS root under the existing app/model data hierarchy, conceptually:

```text
<app-data>/models/tts/<model-id>/
```

Do not store model weights inside the Git repository.

### 10.2 Installer states

Expose truthful states such as:

```text
not_installed
downloading
verifying
promoting
installed
failed
```

### 10.3 Required safety properties

The installer MUST reuse the hardened properties established by Local LLM remediation:

- HTTPS-only initial URLs;
- HTTPS-only redirect targets;
- finite redirect count;
- bounded streaming downloads;
- staging files/directories;
- exact expected size checks;
- streaming SHA-256 verification off the async executor;
- cancellation during download and verification;
- cancellation before promotion/commit;
- atomic promotion/valid marker semantics;
- safe cleanup after cancellation/failure;
- no path traversal;
- no symlink escape;
- no unsafe deletion outside model root;
- chronological safe errors;
- exact pinned metadata.

The implementation should share tested primitives with the Local LLM installer where practical rather than clone a second weaker implementation.

### 10.4 Runtime-use integrity

Before the local TTS runtime first loads an installed model set in a process, verify that the current artifacts still correspond to the pinned catalog identity, using a conservative verification cache comparable to Local LLM runtime-use verification.

Mutation of an installed model/voice/token artifact must fail closed before inference.

## 11. Local TTS Runtime

### 11.1 Runtime manager

Add a shared `LocalTtsRuntimeManager` or equivalent owned by `AppState`.

It must:

- lazily load the selected installed model;
- keep the loaded model warm across utterances;
- serialize or safely coordinate inference according to the chosen runtime's thread-safety contract;
- unload/reload when the selected local model changes;
- expose safe diagnostics;
- never perform network access during synthesis.

`AppState::get_speech_synthesizer()` must not reload an 80 MB model on every utterance.

### 11.2 CPU-only V1

The accepted runtime must explicitly select CPU execution.

No CUDA/GPU availability may be required for startup or synthesis.

Benchmark 1, 2, and a small bounded number of inference threads during the feasibility phase. Freeze a conservative default based on actual Linux/macOS results rather than exposing a premature user tuning knob.

### 11.3 Input processing

The selected text front end must produce phoneme/token input compatible with the official KittenTTS v0.8 model.

A permissive G2P candidate must be tested on a fixed corpus including:

- ordinary Moose sentences;
- contractions;
- punctuation;
- numbers;
- currency;
- dates/times;
- abbreviations;
- possessives;
- common proper names;
- out-of-vocabulary words.

Reference comparison must be against official KittenTTS output or another frozen trusted reference, not merely against itself.

### 11.4 Output contract

The local provider should adapt generated Kitten audio into the existing `AudioStreamData` contract.

Preferred V1 output:

```text
24 kHz
mono
signed 16-bit little-endian PCM bytes
```

If the selected runtime produces `f32`, convert once at the provider boundary with clipping/saturation tests.

Do not write a temporary WAV file just to feed `AudioPlayback`.

The existing playback resampler remains authoritative for conversion to the selected physical output device.

## 12. Cancellation and Concurrency

Local CPU inference is blocking work and must not be allowed to make the async cancellation contract misleading.

### 12.1 Cancellable synthesis contract

Refine `SpeechSynthesizer` so providers receive or can observe the authoritative standalone cancellation token.

The exact Rust shape may vary, but production semantics must be equivalent to:

```rust
async fn synthesize(
    &self,
    request: TtsRequest,
    cancellation: CancellationToken,
) -> Result<AudioStreamData, ProviderError>;
```

Google may cancel by dropping/aborting the in-flight HTTP future.

Local KittenTTS must observe cancellation at the finest safe boundary supported by the runtime, preferably through a generation callback or between bounded chunks.

### 12.2 Blocking isolation

Model load and inference MUST NOT execute large synchronous CPU work directly on a Tokio async executor worker.

Use `spawn_blocking`, a dedicated worker, or an equivalent bounded runtime thread.

### 12.3 Stale completion

A cancelled older local synthesis may not:

- enqueue audio after cancellation;
- change the Moose to `Talking`;
- clear a newer utterance's speech bubble;
- overwrite newer diagnostics as if it were current.

The existing `StandaloneSpeechController` ownership semantics remain authoritative.

## 13. Provider Selection and No-Fallback Policy

`AppState` must select standalone TTS from one immutable settings snapshot for the utterance.

Conceptually:

```text
TtsProvider::Google -> GoogleSpeechSynthesizer
TtsProvider::Local  -> LocalSpeechSynthesizer backed by LocalTtsRuntimeManager
```

Hard requirements:

1. Local selected + model absent → explicit local setup/model error.
2. Local selected + runtime/inference failure → explicit local error.
3. Local selected + cancellation → cancellation, not Google retry.
4. Google selected + API key absent → explicit Google auth/setup error.
5. Google selected + network/model failure → explicit Google error.
6. Google failure MUST NOT fall back to Local.
7. Local failure MUST NOT fall back to Google.
8. Fake synthesizer remains test-only infrastructure and is never a persisted provider.

The local privacy promise is meaningless if a local error silently sends the same text to Google.

---

## 14. Gemini Live Boundary

This project changes **standalone** speech synthesis only.

Gemini Live remains:

```text
microphone / text turn
      ↓
Gemini Live session
      ↓
native Live audio chunks
      ↓
AudioPlayback / CPAL
```

`live_voice` must stay a validated Gemini Live voice and must not be populated from the Kitten voice catalog.

Switching standalone TTS to Local must not alter an active/future Gemini Live voice unless the user separately changes `live_voice`.

## 15. Voice Audition

Voice audition must become provider-aware.

For Local KittenTTS:

- validate the local voice against the local voice catalog;
- require installed/verified local model assets;
- synthesize the fixed audition line locally;
- use the authoritative standalone speech controller/playback path;
- support cancellation/preemption;
- never require a Google API key;
- never send the audition line to a network service.

For Google TTS, preserve current behavior.

Historical Gemini P6 voice-acceptance evidence remains Google-specific and must not be misrepresented as local Kitten voice-quality evidence.

## 17. Privacy and Network Policy

### 17.1 Local synthesis

After required model/runtime assets are installed, local synthesis MUST make no network request.

A network-denial acceptance test must prove that a real local utterance succeeds with networking blocked.

### 17.2 Installation

Model installation may use the network, but:

- no user utterance text is part of the request;
- sources are pinned HTTPS endpoints;
- redirects remain HTTPS;
- downloaded artifacts are cryptographically verified.

### 17.3 Logging

Normal diagnostics/logs MUST NOT contain:

- TTS input text;
- generated transcript text;
- model-download credentials/tokens;
- full sensitive filesystem paths where a safe model ID suffices.

Positive-control privacy tests must prove the local runtime path actually executed while sentinels remain absent from diagnostics/logs.

## 19. Performance Requirements

The feature exists specifically to provide practical CPU local TTS.

### 19.1 Hard requirements

1. no GPU is required;
2. warm real-model synthesis must be faster than real-time (`RTF < 1.0`) on the accepted Linux x86_64 and macOS arm64 reference machines;
3. the runtime must remain responsive enough that cancellation does not wait for an unbounded full paragraph;
4. model loading occurs lazily and is reused across utterances;
5. the selected model payload remains approximately within the Kitten Mini class (~80 MB model, plus bounded support assets/runtime libraries).

### 19.2 Targets

Targets, not automatic pass/fail claims until measured:

- warm median RTF ≤ 0.5;
- warm synthesis latency ≤ 1.5 s for representative short Moose lines;
- cold model initialization ≤ 3 s on the selected reference CPUs;
- no unbounded memory growth across repeated utterances.

The acceptance report must record actual hardware and measured results rather than saying “fast enough” without numbers.

At minimum:

```text
Linux x86_64

macOS x86_64
```

### 20.2 Native/runtime packaging

If the chosen ONNX path adds native libraries:

- package the exact required architecture;

- preserve exact build provenance checks;
- add license/notice collection;
- fail packaging if required native/runtime files are absent.

### 20.3 Model packaging policy

Kitten model weights should be externally installed/cached, not embedded in ordinary application bundles, unless a later explicit release decision changes that policy.

Ordinary CI must remain model-weight-free.

## 21. Testing Strategy

### 21.1 Unit/static tests

Cover at least:

- TTS provider serialization;
- settings v3→v4 migration;
- future settings version rejection;
- Google/local/live voice separation;
- provider-specific voice validation;
- provider capabilities;
- artifact catalog validation;
- unsafe path rejection;
- HTTPS redirect rejection;
- hash/size mismatch;
- installer cancellation races;
- no-fallback routing;
- local model missing failure;
- Google key missing failure;
- PCM f32→i16 conversion if used;
- zero-audio rejection;
- queue-overflow behavior remains shared;
- cancellation during local inference;
- stale completion protection;
- diagnostics privacy.

### 21.2 G2P/reference corpus

Freeze a deterministic English reference corpus and compare the selected permissive phonemizer/tokenizer against an accepted Kitten reference.

The test should fail on meaningful pronunciation/tokenization drift.

### 21.3 Real-model acceptance

A focused acceptance harness must:

1. acquire pinned Kitten assets with cache support;
2. verify exact artifact identity;
3. load on CPU;
4. synthesize representative Moose lines;
5. assert non-empty finite PCM;
6. assert 24 kHz source rate;
7. record model-load latency;
8. record synthesis latency and RTF;
9. test at least several local voices;
10. block network during the actual synthesis phase;
11. prove cancellation/preemption;
12. avoid logging input text.

### 21.4 Cross-platform acceptance

Required evidence:

- Linux x86_64 real-model CPU synthesis;
- macOS arm64 real-model CPU synthesis;
- macOS x86_64 compile/package proof, plus real-model synthesis if runner cost/runtime is reasonable;
- unsigned macOS bundle smoke for both architectures if native runtime packaging changed.

A physical-speaker test is not required to prove synthesis because the shared CPAL playback path already has its own acceptance evidence, but a human local-voice audition is required before declaring voice quality accepted.

## 22. CI Policy

### 22.1 Ordinary CI

Ordinary CI remains model-weight-free and path-scoped.

It should compile/test the local TTS integration where practical without downloading the real Kitten model.

Use fake/small fixtures for logic tests.

### 22.2 Explicit local TTS acceptance

Add a focused explicit acceptance workflow or explicit full-validation path that:

- is exact-head guarded;
- caches the pinned ~80 MB model and native runtime inputs;
- runs real-model synthesis only when explicitly requested;
- runs Linux and macOS jobs in parallel;
- does not rerun unrelated expensive repository gates unnecessarily;
- publishes timing/RTF evidence;
- has a bounded runtime target.

The goal is to avoid repeating the earlier >20-minute full-validation mistake.

### 22.3 Final canonical gate

Before merge, the exact final PR head must also pass the repository's canonical required gates, including literal `npm run check:all` where the repository policy requires it.
