# Talking Moose AI — Product & Technical Specification

## 1. Purpose

Talking Moose AI is a modern reimplementation of the classic desktop Talking Moose concept. It deliberately preserves a cheesy, low-resolution desktop-character presentation while adding modern speech recognition, conversational AI, synthesized speech, memory, limited opt-in desktop awareness, and safe local tooling.

V1 targets:

- Tauri 2 desktop application.
- React + TypeScript + Tailwind frontend.
- Rust backend for privileged/system behavior.
- macOS as the first fully supported production platform.
- Google Gemini for cloud conversation.
- Gemini Live for low-latency conversational reasoning/audio responses.
- Official Moonshine Voice native runtime for local streaming ASR.
- Moonshine Tiny Streaming as the default ASR selection.
- Moonshine Small Streaming as the higher-accuracy local option.
- Google Gemini Live audio input as the explicit cloud-ASR option.
- SQLite for non-secret local application data.
- Operating-system-backed secure storage for credentials.

A feature is complete only when its runtime behavior is wired end-to-end and supported by automated tests or an explicit manual acceptance procedure.

---

## 2. Product principles

1. **Character first.** The Moose is not merely a chat panel with antlers.
2. **Local policy before model policy.** Rust decides whether the Moose may observe, speak, remember, or execute a tool before a model is involved.
3. **Rust owns privileged behavior.** Audio I/O, desktop observation, persistence, secrets, tools, lifecycle, and policy remain in Rust.
4. **Privacy must be enforced.** Disabled settings must remove access to their corresponding runtime path.
5. **Never fabricate observations.** Unsupported, denied, or unavailable observations must be represented explicitly.
6. **No silent production mocks.** Broken microphones, output devices, model files, secret stores, or observers must fail explicitly rather than pretending to work.
7. **Bound every growing resource.** Audio queues, transcripts, retries, observations, tool results, prompt context, and memory retrieval all require hard limits.
8. **Tests are safe by default.** Ordinary tests never contact Google, read a developer credential, or depend on real user state.
9. **Offline/degraded mode remains understandable.** The app still renders and exposes useful local controls when cloud AI is unavailable.
10. **No silent local-to-cloud ASR fallback.** Selecting Moonshine is a privacy decision; a local failure must never begin uploading microphone audio to Google.

## 5. Runtime modes

### 5.1 Production

Production uses real CPAL audio devices, real OS-backed secret storage, real platform observers when permitted, pinned provider/model configuration, and no silent mock substitution. Resource failures return typed errors and the UI explains the degraded capability.

### 5.2 Development/offline

Development may explicitly inject fake AI, fake audio, fake desktop events, and generated test speech. These paths must be selected intentionally.

### 5.3 Tests

Default tests use deterministic fakes, temporary databases/directories, synthetic credentials, and no network/hardware assumptions. Live Google tests require explicit opt-in such as `TALKING_MOOSE_ALLOW_LIVE_API=1` and a dedicated credential.

## 6. ASR architecture

The application owns a provider-neutral ASR contract above specific engines.

```text
Microphone
   |
   +-- Moonshine Tiny Streaming  --+
   |                                |
   +-- Moonshine Small Streaming --+--> provider-neutral ASR events
   |                                |       |
   +-- Gemini Live audio -----------+       +--> conversation lifecycle
```

Provider-neutral events include:

- `SpeechStarted`;
- `PartialTranscript`;
- `FinalTranscript`;
- `SpeechEnded`;
- typed `Error`.

Only one ASR path may own microphone input for an active conversation.

### 6.1 Moonshine mode

Flow:

```text
CPAL microphone
  -> bounded PCM queue
  -> local Moonshine native streaming runtime
  -> partial/final transcript events
  -> final transcript text only
  -> Gemini conversational turn
  -> Gemini/standalone Moose audio response
  -> Rust CPAL playback
```

Raw microphone audio must not be sent to Google in Moonshine modes.

### 6.2 Gemini Live cloud-ASR mode

Flow:

```text
CPAL microphone
  -> bounded PCM queue
  -> Gemini Live audio input
  -> provider transcript/events
  -> Gemini Live audio response
  -> Rust CPAL playback
```

The UI must clearly identify this as cloud audio recognition.

## 7. Moonshine native runtime decision

V1 SHALL use the official Moonshine native runtime rather than sherpa-onnx for Tiny/Small Streaming inference.

Requirements:

- narrow internal Rust FFI module around the official C API;
- unsafe code isolated to the FFI boundary;
- safe RAII wrappers for transcriber and stream handles;
- parent transcriber lifetime retained while child streams exist;
- exact pinned runtime/header/model revisions;
- no floating production model assets;
- explicit runtime-version compatibility checks;
- typed conversion of native errors;
- no native handle leakage on partial construction failure;
- stream stop/free exactly once;
- normal builds may compile without native linkage when the runtime is not being packaged/tested, but runtime use must fail explicitly as unavailable.

The rest of the application must not depend directly on Moonshine implementation types.

## 8. Local model catalog and model manager

V1 local model IDs:

- `moonshine_tiny_streaming` — default/recommended local model;
- `moonshine_small_streaming` — higher-accuracy local model.

Models are downloaded on demand and are not silently bundled into every installer unless a later release decision changes this.

Each manifest entry must include:

- stable application model ID;
- display name;
- upstream immutable revision;
- architecture;
- required files;
- exact byte size where known;
- SHA-256 for every downloaded artifact;
- upstream CRC/checksum as optional secondary integrity metadata;
- runtime/header compatibility;
- license/provenance metadata.

Download/install requirements:

1. explicit user action;
2. HTTPS only;
3. disk-space preflight when practical;
4. bounded download concurrency;
5. `.partial`/staging location;
6. SHA-256 verification before installation;
7. reject corrupt/truncated/wrong-version assets;
8. atomic final install/rename;
9. interrupted-download cleanup/retry;
10. installed-state verification on startup;
11. deletion of inactive models;
12. never delete an in-use model;
13. never silently fall back to cloud audio recognition.

## 9. Settings UX for speech recognition

Settings SHALL expose an **ASR / Speech Recognition** section with three choices:

1. **Moonshine Tiny Streaming** — Recommended / Default; fast and lightweight; local audio.
2. **Moonshine Small Streaming** — better local accuracy at higher CPU/memory cost.
3. **Google Gemini Live (Cloud)** — requires internet and uploads microphone audio during active conversation.

For local models, the UI must show:

- installation state;
- download/install progress;
- manifest-derived size/version;
- Download/Retry/Delete action as appropriate;
- explicit corrupt/missing/incompatible errors;
- local-audio privacy explanation.

Provider switching while an interaction is active must terminate the old microphone/ASR/session graph cleanly and start a fresh graph only after teardown. It must not hot-mutate ownership of an active microphone stream.

New profiles default to Moonshine Tiny Streaming. Legacy profiles created before an ASR selector may migrate to Gemini Live audio to preserve prior behavior; that migration must be explicit/versioned and must not initiate cloud audio unless the user starts a conversation.

## 10. Conversation lifecycle

Rust owns a single authoritative lifecycle. Conceptual states include:

- `Idle`;
- `Connecting`;
- `Listening`;
- `Thinking`;
- `Talking`;
- `Interrupted`;
- `Stopping`;
- `Error`/terminal cleanup.

Hard invariants:

- at most one live conversation/session;
- microphone belongs only to an active conversation or explicit diagnostic test;
- session is not considered active until provider prerequisites/connectivity have succeeded;
- startup is transactional: partial startup failure tears down all resources already acquired;
- stop is idempotent;
- mute stops microphone, ASR, playback, and provider session;
- dismiss stops microphone, ASR, playback, and provider session;
- provider close/error performs the same centralized cleanup;
- app shutdown performs the same centralized cleanup;
- barge-in flushes playback immediately and closes the mouth state;
- provider interrupt is sent where supported;
- stale pre-interruption audio cannot resume later;
- obsolete async callbacks from an old session cannot mutate the current session.

## 11. Audio ownership and correctness

Rust/CPAL is the sole production audio owner.

### 11.1 Capture

- real selected input device or explicit default;
- explicitly selected missing device is an error, not a silent default-device substitution;
- practical `f32`, `i16`, and `u16` formats;
- downmix to mono where required;
- resample to the engine/provider input rate;
- bounded channel;
- defined drop-newest/backpressure behavior;
- dropped-chunk counter;
- rate-limited overload logging;
- callback avoids blocking/allocation where practical;
- capture-active state becomes true only after real stream start succeeds;
- runtime stream failure clears active state and records a typed error.

### 11.2 Playback

- real selected output device or explicit default;
- explicitly selected missing device is an error;
- actual negotiated output rate is authoritative;
- provider/TTS PCM is resampled to that rate;
- practical `f32`, `i16`, `u16` formats;
- bounded playback queue with a hard maximum;
- overflow keeps already queued ordered speech and drops the newest tail;
- queue depth/drop counts exposed to diagnostics;
- flush removes all stale audio and resets mouth/output level;
- browser `speechSynthesis` is not a production speech path.

## 12. macOS microphone permission

The application bundle must contain `NSMicrophoneUsageDescription`.

Permission state must be represented explicitly as:

- `not_requested`;
- `granted`;
- `denied`;
- `unavailable`.

On macOS, AVFoundation authorization status is authoritative. The application must not rely only on parsing CPAL error strings.

Rules:

- permission request occurs only from a clear user action such as a Settings/Privacy button;
- starting a normal conversation while permission is `not_requested` fails with actionable guidance rather than causing an implicit prompt;
- denied/restricted state does not repeatedly prompt;
- UI explains how to open macOS System Settings and grant permission later;
- permission status appears in Privacy and Diagnostics;
- changing permission in System Settings is reflected when status is refreshed.

## 13. Audio diagnostics

Diagnostics must expose, without logging private speech content:

- configured input/output device;
- actual selected input/output device;
- actual capture/output sample rate;
- actual sample format;
- channel count where useful;
- microphone permission state;
- microphone active state;
- current input level;
- current output level;
- playback queue depth and hard limit;
- playback dropped samples;
- microphone dropped chunks;
- last typed input error;
- last typed output error.

User-initiated diagnostics actions:

- Refresh diagnostics;
- Request Microphone Access;
- Test Microphone without contacting Google;
- Test Output with a local generated tone/clip.

Diagnostic microphone tests must not run concurrently with an active conversation.

## 14. Gemini Live requirements

Gemini integration must remain provider-neutral above the Google module.

Required V1 behavior:

- centralized current model configuration;
- setup handshake and explicit ready/ack state;
- input/output transcription events as applicable;
- support text turns for Moonshine final transcripts;
- tools declared in Live setup;
- structured/sanitized provider errors;
- binary and text WebSocket frame parsing;
- bounded reconnect/backoff;
- no unbounded retry loop;
- connection test uses explicit user action and does not expose credentials.

Moonshine partial transcripts are local UI state and must not each become separate Gemini final turns.

## 15. Secrets and privacy

Google credentials:

- never persist in plaintext SQLite;
- use a real OS secure store in production;
- legacy plaintext migration performs secure write, read-back verification, then SQLite deletion;
- secure-write failure preserves the only existing credential;
- frontend may query configured/not-configured but does not receive the stored secret;
- credentials are redacted from provider errors and logs.

Conservative defaults:

- active-app observation Off;
- window-title observation Off/unimplemented unless separately approved;
- memory Off or explicit onboarding choice;
- transcript retention Off or explicit onboarding choice;
- raw audio retention always Off.

Normal logs must not include:

- credentials;
- full prompts;
- transcripts;
- raw/base64 audio;
- full provider frames;
- memory facts;
- window titles or sensitive desktop observations;
- sensitive tool inputs/results.

---

## 16. Desktop observations

V1 macOS observation candidates:

- idle duration;
- sleep/wake;
- battery/power state;
- active application, opt-in.

Window-title collection remains separately gated and Off unless explicitly implemented.

Every observer returns real data or one of denied/unavailable/unsupported/error states. No synthetic placeholder observation may enter a production prompt.

Observations should be summarized locally before becoming model context and retained only for a bounded duration.

---

## 17. Memory and persistence

SQLite stores non-secret application state only.

Requirements:

- schema versioning/migrations;
- settings versioning/migrations;
- deterministic timestamp/order behavior;
- memory read/write gated by `memory_enabled`;
- transcript persistence gated on every path by `save_transcripts`;
- partial/final transcript deduplication;
- observation TTL/pruning;
- bounded query sizes;
- Forget Memory and Forget Everything operations tested end-to-end;
- no silent production fallback to an in-memory database when persistent DB initialization fails.

---

## 18. Tools and model authority

Tool execution is mediated by Rust.

Every tool requires:

- stable name/description;
- schema;
- permission classification;
- bounded input/output size;
- timeout;
- structured error;
- privacy-safe audit metadata.

V1 must not expose generic shell, filesystem, arbitrary AppleScript, arbitrary HTTP, dynamic code, or unrestricted process execution to a model.

Settings/privacy gates are checked at dispatch time, not only when schemas are created.

---

## 19. Character, prompting, voice, and ambient behavior

Character behavior is deterministic policy plus model generation, not model policy alone.

- personality/talkativeness/quiet-hours settings update live Rust policy immediately;
- quiet hours use local wall-clock time while cooldown arithmetic remains monotonic/UTC-safe;
- prompt context has hard budgets;
- memory/observation/tool context is included only when permitted/relevant;
- ambient comments are locally scheduled and filtered by cooldown/dedup/annoyance budget;
- model output cannot bypass local speak/no-speak policy;
- voice direction remains an original cantankerous cartoon moose, not an imitation of a protected performer;
- standalone TTS uses Rust playback and typed errors/cancellation.

## 21. Failure policy

The following failures must be explicit and recoverable where possible:

- no microphone;
- selected microphone missing;
- microphone permission not requested/denied;
- selected output missing;
- output configuration/build/start failure;
- Moonshine runtime unavailable/incompatible;
- model not installed;
- model corrupt;
- model download interrupted/checksum mismatch;
- Gemini unavailable/auth failure;
- provider disconnect;
- database failure;
- secret-store failure;
- tool timeout/permission denial.

A subsystem must never claim `running`, `installed`, `connected`, or `granted` before the corresponding operation has actually succeeded.

## 22. Resource limits

V1 requires hard bounds for:

- microphone queue;
- playback queue;
- ASR queue;
- download concurrency;
- provider reconnect attempts/backoff;
- transcript queries/retention;
- observation retention;
- tool payload/result size;
- prompt/context length;
- memory retrieval count;
- logs.

CPU-only local ASR is first class. Tiny/Small performance must be measured on representative CPU-only macOS hardware before release. The release requirement is faster-than-real-time sustained recognition for the minimum supported reference CPU, with measured memory/CPU reported in diagnostics/benchmark documentation.

## 25. V1 acceptance checklist

V1 is complete only when all of the following are demonstrated:

### Product/lifecycle

- [ ] Moose art/states/animations are production-ready and original.
- [ ] Click-to-talk starts one real conversation.
- [ ] Stop, mute, dismiss, provider loss, and shutdown always stop microphone/session/playback.
- [ ] Barge-in prevents stale speech from resuming.
- [ ] Mouth follows actual Rust playback.

### Audio

- [ ] Rust owns production input/output.
- [ ] Input/output selection works.
- [ ] Common macOS CPAL formats work.
- [ ] Playback uses actual device rate.
- [ ] Microphone/playback queues are bounded.
- [ ] Permission/device failure never masquerades as success.

### Local ASR

- [ ] New profiles default to Tiny Streaming.
- [ ] Tiny downloads, SHA-256 verifies, atomically installs, loads, streams, and deletes.
- [ ] Small downloads, SHA-256 verifies, atomically installs, loads, streams, and deletes.
- [ ] Official native Moonshine streaming API is used through the narrow safe wrapper.
- [ ] Partial transcript updates stay local.
- [ ] Final local transcript produces a normal Gemini conversational/audio response.
- [ ] Raw microphone audio never reaches Google in Moonshine modes.
- [ ] Local failure never silently becomes cloud audio ASR.
- [ ] CPU-only local ASR is faster than real time on the minimum reference CPU.

### Gemini

- [ ] Live setup reaches ready/ack state.
- [ ] Transcript events are correct for cloud/local modes.
- [ ] Tool declarations/responses are wired.
- [ ] Errors are structured/sanitized.
- [ ] Reconnect is bounded.

### Privacy/security

- [ ] No Google credential in SQLite.
- [ ] Credential survives restart in OS secure storage.
- [ ] Normal logs contain no transcript/full prompt/full frame/raw audio/credential.
- [ ] Default tests cannot call live Google.
- [ ] Runtime privacy settings are enforced.
- [ ] No fabricated desktop observations.
- [ ] No arbitrary execution tool exists.

### Data/settings

- [ ] Settings/database schemas migrate cleanly.
- [ ] Memory and transcript retention gates cover every path.
- [ ] Observation retention is bounded.
- [ ] Forget operations are tested.

### Release

- [ ] Full quality command passes.
- [ ] CI mirrors it.
- [ ] Accessibility pass is complete.
- [ ] Signed/notarized app artifact is produced.
- [ ] Packaged Moonshine runtime loads on a clean machine.
- [ ] Clean-profile model management works.

## 27. Product litmus test

V1 succeeds when a user can install the macOS app, clearly understand local-versus-cloud speech recognition, download and use the default Moonshine Tiny model, click a ridiculous low-resolution Moose, hold a fluid spoken conversation, interrupt it naturally, mute or dismiss it knowing the microphone truly stops, optionally allow sparse context-aware comments without invasive monitoring, explicitly allow useful memory, remove that memory later, and operate the app without silent cloud fallback, fabricated observations, hidden private logging, or unbounded resource growth.
