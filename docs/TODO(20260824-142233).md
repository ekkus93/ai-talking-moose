## Tracker rules

- `[x]` means the criterion is implemented **and** proven by a test that exercises the production path.
- `[ ]` means implementation or proof remains.
- **A test that asserts against a `#[cfg(test)]` re-implementation of a production branch does not close any row here.** This pattern is what allowed prior rows to be ticked incorrectly.
- Partial completion is recorded inline on the row with its reason. Do not tick a row to represent "mostly done".
- Concurrency rows require a test that exercises the interleaving, not the sequential path.
- Privacy rows require log/output capture from the subsystem that actually handles that data class.
- Severity tags (`S1`–`S4`) are defined in `SPEC(20260824-142233).md` §3. Work is ordered by severity, not phase number.
