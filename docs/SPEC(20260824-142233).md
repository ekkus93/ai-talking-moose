## 1. Purpose

A full source-level code review of the frontend and backend, followed by a skeptical re-audit of the `TODO(20260818-163801).md` checkbox state, produced a set of confirmed defects. This document specifies the required end state for each one.

Every **new remediation finding** here originates from a defect **verified against source**, not inferred. Where a finding was reported but could not be confirmed, it is recorded in §11 as unverified rather than promoted to a requirement. `V1R-183` is the sole exception to the source-verified claim: it carries forward previously specified acceptance obligations from `TODO(20260818-163801).md` whose completion remains unverified or open, and which are therefore *uncompleted work* rather than *newly confirmed defects*.

**Amended 2026-08-24** following external review (`REVIEW_QUESTIONS(20260824-143800).md`); responses recorded in `REVIEW_RESPONSES(20260824-143800).md`. Six requirements were corrected after re-verifying their underlying claims against source — three of them because the requirement as originally written was contradictory, technically impossible, or demanded a contract the architecture does not provide. Those corrections are marked inline in §4, §5, §7, and §8.

This specification exists because the prior TODO could not be trusted as a completion signal. Two independent failure modes were found:

1. **Under-reporting.** Large parts of P6–P13 were implemented and tested but left unchecked.
2. **Over-reporting.** Several rows were checked despite the underlying capability being absent, unreachable, or proven only by a test that cannot fail.

The second failure mode is the more dangerous, and §7 specifies structural countermeasures against its recurrence.

## 3. Severity model

Remediation items carry one of four severities. The companion TODO orders work by severity, not by phase number.

- **S1 — Correctness under concurrency or failure.** A race, panic, silent data loss, or stuck state that can occur in normal operation. Must be fixed before V1.
- **S2 — Privacy or test-integrity defect.** A privacy control whose enforcement is unproven, or a test that cannot fail when its production path regresses. Must be fixed before V1, because these defects hide other defects.
- **S3 — User-visible defect.** Incorrect or misleading behavior a user can observe, including accessibility barriers. Must be fixed before V1.
- **S4 — Structural.** Duplication, dead code, or coarse locking that has not yet produced a user-visible defect but has already caused divergence or blocks safe change. Fix before V1 where cheap; otherwise record an explicit deferral.

A requirement is complete only when its runtime behavior is correct **and** a test exercises the production path. A test that duplicates a production branch instead of calling it does not satisfy any requirement in this document (see §7).

## 4. Backend correctness and concurrency (P14)

### 4.1 Generation-safety across await points

Two paths check the session generation **before** awaiting a lock and then act **without re-checking** after the lock resolves:

- the tool-call response path in `conversation/session/event_loop.rs`;
- the microphone-chunk forwarding path in `conversation/session.rs` → `forward_microphone_chunk`.

If `stop_session` / `start_session` interleaves in that window, an old generation's tool response or microphone audio is delivered into a **newly started session**. In `GeminiLiveAudio` mode this means microphone audio crossing a session boundary.

**Required end state.** Generation/session identity is validated immediately before a send is accepted, and a stale handle cannot cross into a newly started session. Deterministic tests must exercise the interleaving, not merely the happy path.

**Corrected 2026-08-24.** An earlier draft of this requirement cited `handle_local_asr_event` as the pattern to adopt. That was wrong and self-contradictory: it acquires `operation_lock` at `session.rs:346` and holds it through `send_text_turn().await` at `:389` — precisely the granularity §6.4 requires removed. This section specifies the **generation invariant only** and prescribes no lock scope; the lock and cancellation model is owned by §6.4 and must be designed jointly with it. No global `operation_lock` may be held across provider/network I/O in the resulting design.

### 4.2 Capture start is not atomic with its running flag

`audio/capture.rs` calls `stream.play()` and only afterwards stores `is_running = true`; the input callback no-ops while that flag is false. The driver may invoke the callback in between, discarding the first captured audio of every session.

**Required end state.** No captured audio is discarded due to startup ordering. The running state is established before the stream can deliver callbacks, or early callbacks are buffered rather than dropped.

### 4.3 Outbound provider messages may be silently discarded

`ai/google/live.rs` returns `Ok(())` once a message is queued, but `drain_disconnected_messages` discards queued non-`Close` messages on reconnect, and a failed `socket.send()` drops that message. No error reaches the caller. For a tool response this can leave the model's `functionCall` permanently unanswered.

**Required end state.** The meaning of `Ok(())` at the public Live-session API boundary is documented explicitly, delivery states are defined, tool responses are retained across reconnect until a bounded terminal outcome, and terminal failure returns a typed error. Loss, retry, and failure counts must be observable in diagnostics.

**Corrected 2026-08-24.** An earlier draft required a failed `socket.send()` to surface a typed error "to its caller". The architecture is `caller → mpsc::Sender<Message>` (`live.rs:630`) `→ supervisor → socket.send()`; the caller's `Ok(())` today means *accepted into the local channel*, and the supervisor writes later. Surfacing a transport error to the original caller therefore requires a **contract change** — a per-message oneshot acknowledgement or an equivalent outbound-queue abstraction — which the requirement must specify rather than assume. Note also that transport-write success does not prove the service processed the message absent an application-level acknowledgement. This work is coordinated with §6.4's timeout and cancellation semantics.

### 4.4 ASR transcript state machine

In `asr/transcript_state.rs` the blank-text early return precedes the `is_final` branch, so a whitespace-only final update never closes the active segment: no `FinalTranscript`, no `SpeechEnded`, `active` stays `Some`. If it is the last utterance before stop, speaking state remains stuck until an unrelated non-blank segment arrives.

**Required end state.** A final update always closes its segment regardless of text content. A blank final emits `SpeechEnded` and clears `active`, with or without an empty `FinalTranscript`, and the choice is tested.

### 4.5 ASR worker lifecycle

Two defects:

- Cancelling `start_architecture` while awaiting readiness drops the `JoinHandle`, **detaching** rather than stopping the native inference thread. It continues running, orphaned and unobservable.
- `MoonshineStream::stop()` sets `started = false` only on success, so an error path leaves `Drop` calling `stop_stream` a second time on the same native handle.

**Required end state.** Cancelling startup leaves an identified owner responsible for the worker; cancellation is signalled cooperatively; when the native call returns the worker observes cancellation, tears down, and exits; the worker remains joinable rather than detached; startup is bounded where the native API permits a meaningful timeout. `stop_stream` is called at most once per handle on every path, including error paths.

**Corrected 2026-08-24.** An earlier draft required cancellation to "join or abort" the worker. The worker is a real OS thread (`pipeline.rs:16` imports `std::thread::JoinHandle`; `:94` holds `Option<JoinHandle<…>>`, reaped via `spawn_blocking(|| worker.join())`), and Rust provides **no safe forced abort of an arbitrary OS thread** — the worker may be inside a blocking native initialization call. The requirement is therefore restated in terms of cooperative cancellation and retained ownership. The real defect is ownership/joinability while readiness is outstanding, not a permanently live thread after initialization returns.

### 4.6 Panics and fault tolerance

- `ai/google/auth.rs::masked_key()` slices the key by byte offset (`[..4]`, `[len-4..]`) without checking UTF-8 boundaries; a non-ASCII key panics. Currently no callers — live the moment one is added.
- A transient OS-keychain failure during one-time legacy-key migration propagates out of `setup()` and panics application startup, even though the legacy key is safely preserved in SQLite and would migrate on the next launch.
- `persistence/sqlite/crud.rs` uses bare `.lock().unwrap()` at 13 call sites. One unrelated panic while holding the DB lock poisons it and panics every subsequent settings, memory, and transcript operation for the process lifetime. `desktop/runtime.rs` already self-heals from poisoning; the database does not.

**Required end state.** No reachable panic from malformed credential input. Keychain migration failure degrades rather than aborting startup, preserving the legacy row. Database lock poisoning is recovered from or contained, consistent with the approach already used in `desktop/runtime.rs`.

### 4.7 Model installer robustness

- `verify_installed` is called from engine startup **without** `install_operation_lock`, so a concurrent `delete_installed` can remove the model directory between verification and native load. Fails closed, but the lock elsewhere implies this was meant to be covered.
- `install_asr_model` / `delete_asr_model` never take `settings_runtime_lock`, so a delete can race a conversation start selecting the same model. `ensure_model_mutation_allowed` is checked once, not held.
- `.replaced` backup directories from failed promotion cleanup are never swept — `cleanup_stale_partials` matches only `.partial` — leaking up to ~165 MB permanently.
- A TOCTOU gap exists between the symlink-rejection `symlink_metadata` check and the later `File::open`, which follows symlinks.

**Required end state.** Verification and load are atomic with respect to deletion. Model mutation and conversation start cannot interleave destructively. Stale `.replaced` directories are swept. Symlink rejection is not bypassable by a path swap between check and open.

### 4.8 Clock-regression handling

`character/cooldown.rs::AnnoyanceBudget::update_decay` clamps elapsed time to zero when `now` precedes the last checkpoint, but still overwrites `last_decay_check` with that earlier value — so the next correctly-ordered call double-credits decay.

**Required end state.** A backward clock step neither credits decay nor corrupts the checkpoint. Tested explicitly.

### 4.9 Minor correctness

- `audio/resample.rs::resample_linear` can under-produce by one sample at rounding edges because `idx0` is not clamped the way `idx1` is, violating its own length contract.
- `commands/ambient.rs` treats `queued_samples == 0` as synthesis failure; the equivalent interactive paths in `commands/character.rs` and `commands/conversation.rs` do not. The same "zero playable audio" condition is caught on one path and silently swallowed on two others.

**Required end state.** The resampler honors its documented output length. All three speech paths agree on what constitutes synthesis failure — necessarily so, once §6.1 unifies them.

## 5. Frontend correctness (P15)

### 5.1 Store correctness

- `hasApiKey` is set only inside `loadSettings()`, which runs once on mount. Both the Settings save path and the onboarding save path call `setGoogleApiKey` without refreshing it, so the title-bar badge reads "AI: NO KEY" until restart despite a valid stored key.
- Locally-appended transcript records mint `id: Date.now()` at two sites. At 1 ms resolution, two finalize events in the same millisecond collide, and `TranscriptDrawer` keys its list on that id — React may drop or misrender an entry.
- The Live/Text model `<select>` elements render options only from the async-loaded `googleModels`, which starts empty. Until it resolves, `value` matches no option, so the control misrepresents the current selection and a user interacting during that window can write a model they did not intend to choose.

**Required end state.** Saving a key updates key-presence state immediately. Transcript ids are collision-free. The model selector shows an explicit loading state, preserves the persisted selection while loading, and never writes a setting merely from being rendered or opened.

**Corrected 2026-08-24.** An earlier draft claimed a *persisted stale model id* could silently resolve to a different model. That mechanism is **not reachable**: `AppSettings::from_persisted_json` normalizes both ids (`app/state.rs:146-151`), covered by `stale_or_wrong_capability_models_normalize_to_current_defaults` (`ai/google/config.rs:318`). Opening a `<select>` also does not itself fire `onChange`. The provable defect is narrower — the catalog-loading window above — and the requirement is rescoped to it. No workaround for stale-id mutation is to be implemented.

### 5.2 Settings write discipline

Every settings control writes through on each `onChange`. A range-slider drag emits many events per second, each triggering a full IPC round-trip and a full settings-object persist.

**Required end state.** Continuous controls coalesce writes; runtime behavior still updates responsively. No behavioral setting requires a modal commit step.

### 5.3 Voice catalog unification

The Voice & Audio tab hardcodes six TTS voices in JSX while `P6VoiceAcceptancePanel` fetches the authoritative ~30-voice catalog from the backend. The primary settings screen therefore misrepresents what is selectable, and the two lists can drift.

**Required end state.** One catalog, backend-derived, used by every voice selector.

### 5.4 Production surface hygiene

- `P6VoiceAcceptancePanel` is phase-acceptance tooling rendered unconditionally in production Settings; its own copy describes an unresolved QA listening pass.
- `tauriBridge.clearGoogleApiKey()` has no caller — there is no way to remove a stored key from the UI despite backend support.
- `mooseStore.triggerAmbient` is reachable only from a test.

**Required end state.** Acceptance-only UI is gated out of production builds or removed. Either the key-removal affordance is exposed or the unused bridge export is deleted. No store action is reachable only from tests.

## 6. Architecture consolidation (P16)

### 6.1 Speech command duplication

`speak_standalone`-equivalent logic — read voice settings, synthesize, inspect dropped/queued samples — is implemented three times across `commands/ambient.rs`, `commands/character.rs`, and inline in `commands/conversation.rs`. **They already disagree** on failure detection (§4.9). `transition_and_emit` is duplicated identically in all three; `show_character` is byte-identical between two.

**Required end state.** One speech-invocation helper and one transition/emit helper, used by every command path. Divergence becomes impossible by construction rather than by review.

### 6.2 Platform stub is never compiled

`desktop/mod.rs`'s `cfg` selection means `desktop/macos_stub.rs` is **never compiled under `cargo test`, even on non-macOS CI** — the `cfg(test)` arm always wins. It is a hand-maintained parallel implementation of the observer contract with zero compile or test coverage, free to drift silently.

**Required end state.** Every platform implementation of the observer contract is compiled and contract-tested in CI, or deleted.

### 6.3 Character state model

- `CharacterState::Annoyed` and `::Sleeping` are wired into the transition table but have **zero production call sites**, with corresponding dead frontend sprite support.
- Mute is represented twice — as `CharacterState::Muted` and as an independent `Arc<RwLock<bool>>` consumed by `AmbientPolicyContext` — kept consistent only because one call site happens to set both. Nothing enforces the invariant.

**Required end state.** Unreachable states are either driven by real behavior or removed along with their frontend support. Mute has a single authoritative representation, or the invariant binding the two is enforced in one place and tested.

### 6.4 Lock granularity and I/O timeouts

`conversation/session.rs` holds `operation_lock` across `provider.connect()`, `send_text_turn()`, and `interrupt()` — all network calls, none with a timeout. A stalled network call blocks `start_session`, `stop_session`, and `barge_in`. Separately, `install_operation_lock` is process-wide, so installing Tiny blocks installing or deleting the unrelated Small model.

**Required end state.** No unbounded network wait occurs while holding a lock that user-initiated Stop or barge-in requires. Model install locking is per-model.

### 6.5 Fail-closed defaults

`character/behavior.rs::AmbientPolicyContext::default()` sets `privacy_allowed: true`. Safe only because production always constructs an explicit context; a future caller reaching for the ergonomic default silently bypasses the privacy gate.

**Required end state.** Privacy-relevant defaults deny. A default-constructed policy context cannot permit ambient speech.

### 6.6 Credential transport

The API key is sent as a **URL query parameter** on all three network paths (`text.rs`, `tts.rs`, `live.rs`). Only `text.rs` redacts it from error strings; `tts.rs` and `live.rs` do not. Any future `debug!`/trace logging or proxy capture on those paths leaks the raw key.

**Required end state.** The key is transmitted via header where the API permits it; where it cannot be, redaction is applied uniformly on every path rather than one. Redaction covers tracing output, not only frontend-facing error strings.

### 6.7 Conversion duplication

`audio/playback.rs` reimplements f32↔i16 conversion that already exists in `audio/resample.rs`.

**Required end state.** One conversion implementation.

## 7. Configuration truth and test integrity (P17, P18)

### 7.1 Dead settings

Three settings are persisted, range-validated, and user-facing, but **have no runtime consumer**:

| Setting | Evidence |
| --- | --- |
| `volume` | Only reference outside its declaration is the range validator; no gain stage exists in `audio/` |
| `hide_delay_seconds` | Ambient hide interval is the hardcoded `AMBIENT_IDLE_AFTER_SPEECH` constant |
| `tts_model` | `GoogleSpeechSynthesizer::new` receives only `tts_voice`; the model is hardcoded internally |

`BehaviorConfig::min_cooldown_seconds` is likewise hardcoded with no settings field feeding it.

**Required end state.** Each is either wired to real runtime behavior or removed from the schema, the validator, and the UI. A setting that persists and validates but does nothing is a correctness defect, not cosmetic: it misrepresents the product to the user.

The governing invariant is: **every persisted *user-configurable* setting has an identified production consumer, or is explicitly classified as persistence/migration metadata or runtime-derived state.** No user-facing control may persist a value the runtime ignores.

**Corrected 2026-08-24.** An earlier draft required a test asserting that *every persisted setting* has an observable runtime effect. That encodes the wrong abstraction: `settings_version` is migration metadata, and `microphone_permission_granted` is OS-derived runtime state (§7.2a) that should not be persisted at all. A literal reading would force artificial consumers for both.

### 7.2 Single source of defaults

`src/lib/tauriBridge.ts` holds a second full `AppSettings` default blob for the non-Tauri browser path, and it **diverges** from Rust: `microphone_permission_granted` is `false` there and `true` in `app/state.rs`. It also hardcodes model ids rather than deriving them. Three further hand-maintained copies exist under `src/test/`. Nothing asserts any of them match.

**Required end state.** One authoritative defaults definition. Any mirror is generated from it or asserted equal to it by a test that fails on divergence.

### 7.2a `microphone_permission_granted` is runtime state in a persisted document

`commands/settings.rs:95` overwrites this field with `microphone_permission_state().is_granted()` on every read, so the persisted value is **never authoritative**. The `false`/`true` default divergence in §7.2 is a symptom of the field existing in persisted `AppSettings` at all, not a defect in either default. The UI likewise presents it as OS state, not a saved preference.

**Required end state.** OS-derived microphone permission is removed from persisted `AppSettings` and represented as runtime/diagnostic state through the dedicated microphone-permission API — which also aligns this with §8.5. If compatibility requires the field to remain serialized, that reason is documented along with exactly how it is prevented from becoming authoritative. Making the two defaults agree on an arbitrary persisted value is explicitly **not** the fix.

### 7.3 Tests must exercise production paths

The audit found a recurring, dangerous pattern: **tests that assert against `#[cfg(test)]` helpers which re-implement a production branch rather than calling it.** The confirmed instance is `model_prompt_memories`, a test-only duplicate used to "prove" the memory-off privacy gate. Deleting the production gate would not fail that test.

**Required end state.** No test-only re-implementation stands in for a production code path in any privacy or correctness test. Where a production path is hard to reach from a test, it is refactored to be reachable rather than mirrored. This is the highest-leverage item in this document: it is the mechanism by which the other defects stayed invisible.

### 7.4 Logging-privacy proof breadth

All seven logging-privacy claims rest on a single log-capturing test that exercises only `ToolRouter::dispatch`. It is the only log-capturing test in the backend. Nothing exercises the ASR, session, provider, or prompt-builder logging paths — which are precisely the paths that handle transcripts, prompts, audio, and memory text. Grepping non-test logging suggests the behavior holds; the suite does not prove it.

Additionally, secret redaction is a literal `str::replace` applied at three call sites, all on error strings returned to the frontend — **not** on tracing output.

**Required end state.** Each privacy claim is proven by a test capturing logs from the subsystem that actually handles that data class. Redaction covers tracing output.

### 7.5 Vacuous and mis-cited tests

- `app/tray.rs::tray_actions_are_explicit_and_bounded` asserts that an 8-element array literal has length 8. It proves nothing.
- `docs/RECONCILIATION_P12_20260823.md` credits barge-in coverage to a test that uses an empty playback queue and asserts none of the claimed behavior; the actual coverage lives in a different test.

**Required end state.** No test asserts a property of its own literal. Reconciliation documents cite tests that assert what is claimed.

### 7.6 Remaining coverage gaps

Genuinely open from the original plan and still required: the V1R-121 failure matrix, the V1R-124 network-denial harness and no-ordinary-download guarantee, and the V1R-125 mute/dismiss race, queue-overload, and device-error scenarios.

## 8. Accessibility, onboarding, and tool policy (P19)

### 8.1 Reduced motion is not implemented

`prefers-reduced-motion` appears exactly once in the repository, in `src/index.css`, and `matchMedia` appears nowhere in TypeScript. The block collapses CSS animation and transition durations — but **both real animations are JS-driven and entirely ungated**: the recursive blink `setTimeout` chain, and per-audio-chunk mouth-frame sprite swaps driven from the store.

Compounding this, the modal animation classes the CSS block would nominally cover (`animate-in`, `fade-in`, `zoom-in-95`, `slide-in-from-bottom-5`) **do not exist**: `tailwindcss-animate` is not a dependency, `tailwind.config.js` has `plugins: []`, and none of those classes appear in the built bundle.

**Required end state.** Reduced-motion preference is observed in JavaScript and suppresses or stills the blink cycle and mouth animation. Dead animation class names are removed or their plugin is installed.

### 8.2 Semantic labels and live regions

- The ASR download progress bar is a plain `div` carrying `aria-label` with no `role="progressbar"` and no `aria-valuenow`; the label is ignored by the accessible-name algorithm.
- The transcript container has no `role="log"` / `aria-live`, so streaming partials and finalized turns are never announced.

**Required end state.** Progress and streaming-transcript regions expose correct roles and live-region semantics.

### 8.3 Focus management

None of the three `aria-modal="true"` dialogs implements a focus trap; only one restores focus on close. The global `:focus-visible` ring is `#111`, invisible against the black title bar where two controls live.

**Required end state.** Modal dialogs trap focus and restore it on close. The focus indicator is visible against every background it can appear on.

### 8.4 Onboarding completeness

Onboarding **writes no settings**; it only describes the conservative defaults, which come from `AppSettings::default`. More seriously, there is no onboarding-completion flag — the modal opens purely on `!hasApiKey`, so any user who already has a key **never sees the privacy explanations at all**. Legacy profiles migrated to `AsrMode::GeminiLiveAudio` never re-run onboarding, which is exactly the population placed on cloud microphone audio.

**Required end state — decided 2026-08-24: onboarding is explanatory.** It is not a second settings editor and writes no privacy choices; conservative defaults continue to originate from `AppSettings::default()` and change only in Settings. An independent, **versioned** onboarding-completion marker is added; privacy and local-vs-cloud explanations are shown whenever the relevant onboarding version has not been acknowledged, regardless of key presence; and profiles migrated to `AsrMode::GeminiLiveAudio` receive the cloud-audio explanation.

### 8.5 Live microphone permission state

The permission card is fetch-on-mount plus a manual refresh button — no polling, no subscription. Granting permission in System Settings leaves the panel stale. First paint renders a factually false "unavailable on this platform" before the async result lands, and the request action renders only in the `not_requested` state.

**Required end state.** Displayed permission state converges without a manual refresh, and no false platform-unavailability claim is rendered while state is loading.

### 8.6 Tool confirmation policy

`ToolConfirmationPolicy::PerInvocation` and `ToolInvocationContext.user_confirmed` exist, but **no tool declares `PerInvocation`, no production path sets `user_confirmed`, `dispatch_with_context` has no non-test caller, and no confirmation UI exists** anywhere in the frontend. The confirmation branches are reachable only by tests calling the private predicate directly. V1 declares no consequential action tool, so the guard rail has an empty membership set.

**Required end state — decided 2026-08-24: deferred for V1.** No V1 tool is a consequential action requiring per-invocation confirmation, so confirmation UI and dispatch wiring are **not** built for an empty membership set. `PerInvocation` and `user_confirmed` are documented in `docs/TOOLS_V1_POLICY.md` as forward-looking infrastructure with an explicitly empty V1 membership set; policy-primitive tests are retained only where they are useful and not misleading about end-to-end coverage. The requirement reopens with full end-to-end criteria if a shipping tool ever requires confirmation. What remains prohibited is representing the current state as implemented.

### 8.7 Tool audit observability

Audit recording works into a 128-entry ring buffer, but `audit_snapshot()` has no production caller, no Tauri command exposes it, and the tracing emission omits `duration_ms`. Timing is recorded only where nothing can read it.

**Required end state.** The audit trail is reachable by the user or by diagnostics, including timing — or the timing field is removed and the requirement narrowed to what actually ships.

## 12. Definition of done

A P14–P20 item is complete when all of the following hold:

1. The defect is repaired in production code, not worked around at a call site.
2. A test exercises the **production** path — not a `#[cfg(test)]` mirror of it (§7.3).
3. For concurrency defects, the test exercises the interleaving, not only the sequential path.
4. For privacy defects, the proof captures output from the subsystem that handles the data class.
5. `npm run check:all` passes.
6. The corresponding TODO row is checked only after 1–5 hold, and any partial completion is recorded inline with its reason rather than by ticking the row.

## 13. Acceptance checklist

### Concurrency and correctness
- [ ] No send crossing an await boundary acts on a stale generation.
- [ ] No captured audio is lost to capture-start ordering.
- [ ] No outbound provider message is dropped without a typed error.
- [ ] A blank final transcript always closes its utterance.
- [ ] No orphaned native inference thread survives a cancelled start.
- [ ] `stop_stream` is called at most once per handle on every path.

### Fault tolerance
- [ ] No reachable panic from credential input.
- [ ] Keychain migration failure degrades instead of aborting startup.
- [ ] Database lock poisoning cannot brick persistence for the process lifetime.

### Privacy and test integrity
- [ ] No privacy or correctness test asserts against a test-only re-implementation.
- [ ] Each logging-privacy claim is proven from the subsystem that handles that data class.
- [ ] Redaction covers tracing output.
- [ ] A default-constructed ambient policy context denies.

### Configuration truth
- [ ] Every persisted setting affects runtime behavior or has been removed.
- [ ] One authoritative defaults definition; divergence fails a test.

### User-visible
